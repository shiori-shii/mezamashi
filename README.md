# ホログラム目覚まし

就寝前ルーティン・目覚まし・睡眠記録をホログラムバッジで続けるための個人用ツール。
ビルド不要の単一ページ構成（HTML / CSS / JS をすべて `index.html` に同梱）。

## 構成

| ファイル | 役割 |
|---|---|
| `index.html` | 本体。UI・アラームエンジン・QR読み取り・カレンダーのすべて |
| `manifest.webmanifest` | PWA定義（ホーム画面追加・全画面起動） |
| `sw.js` | Service Worker（ネットワーク優先・オフライン予備） |
| `icon-*.png` | アプリアイコン（スクリプト生成） |

データは端末の `localStorage`（キー `mezamashi.v1`）にのみ保存される。サーバーには何も送信しない。

## 使い方

1. iPhoneのSafariで公開URLを開く
2. 共有メニュー →「ホーム画面に追加」
3. ホーム画面のアイコンから起動する（全画面・カメラ利用可）

## 機能

- **就寝前ルーティン**：タスクの追加／編集／削除、1個ごとのCLEAR演出、全完了でホログラムバッジ
- **目覚まし**：時刻設定、音3種、QRコード停止、Screen Wake Lock
- **睡眠記録**：就寝・起床がそろって1バッジ（低いほうのランクを採用）
- **カレンダー**：2週間表示（既定）／月表示、週ごとの達成率バッジ

### バッジ条件

| 予定時刻との差 | バッジ |
|---|---|
| 予定以前 | ホログラム |
| +15分以内 | 金 |
| +30分以内 | 銀 |
| +45分以内 | 銅 |
| 45分超 | なし |

週バッジは「就寝・起床セットを達成した日数 / 7」で、7/7=ホログラム、6/7=金、5/7=銀。

## アラームの仕組みと制約

鳴動の確実性のため、鳴る瞬間を `setTimeout` ではなく **AudioContext のゲインに予約**している
（オーディオスレッド側で発火するため、JSタイマーが絞られても鳴る）。
加えて**無音WAVを `loop=true` で再生し続けて**オーディオセッションを保持する。
鳴動時は WebAudio と HTMLAudio の両経路で鳴らす。

### 重要：無音ループの再生継続を JS に依存させないこと

無音を `loop=false` にして `ended` ごとに再生し直す実装にしたところ、
iOSが画面OFF時にJSを凍結した瞬間に再生が途切れ、オーディオセッションごと終了して
**アラームが鳴らなくなった**。`loop=true` に戻すことで解消している。
`timeupdate` は鳴動漏れの見張りとしてのみ使い、再生の継続には関与させない。

### iOS（ホーム画面に追加したPWA）での動作確認結果

| 条件 | 結果 |
|---|---|
| 音が鳴る | ○ |
| マナーモード（消音スイッチON） | ○ |
| 画面を点けたまま | ○ |
| 画面を消す | ○ |
| 他アプリに切り替える | ○ |
| QRコードでの停止 | ○ |

アプリを完全に終了（Appスイッチャーで上スワイプ）すると鳴らない。
一晩待機させるため、充電しながらの使用を推奨。

カメラ（QR読み取り）は claude.ai の iframe 内では権限が渡らないため動作しない。
自前オリジン（GitHub Pages）でホストすることで解決している。

## 開発

ローカルで `index.html` をブラウザで開けばそのまま動作する。
ただし **カメラ（QR読み取り）は HTTPS でのみ動作する**ため、QRの確認は公開URLで行う。

```sh
# 更新を公開する
git add -A
git commit -m "変更内容"
git push
```

GitHub Pages が自動で再デプロイする（反映まで1分程度）。

## アイコンの再生成

`icon-*.png` は Pillow 不要のスクリプトで生成している（`zlib` で直接PNGを書き出す）。
配色やデザインを変える場合は生成スクリプトを修正して差し替える。
